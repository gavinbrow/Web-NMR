# Scientific support features

`measureKinetics(spectra, options)` measures full-resolution signed areas from processed real data. Input limits use the displayed ppm scale, including each spectrum's reference offset. Membership can be restricted with `spectrumIds`; invalid rows retain diagnostics and cannot become fit observations.

- **Area:** target signed area in intensity·ppm.
- **Ratio:** target area / internal standard area × standard signal proton count / target signal proton count.
- **Concentration:** ratio × known internal standard concentration. The result uses the concentration unit supplied by the user.

Display gains, stack normalization, and integral reporting scales do not enter measurements. Target and standard regions must be disjoint and fully contained in each spectrum. Nonpositive or effectively zero standard areas, invalid proton counts, and missing times are reported per row. `kineticsPoints(rows)` selects valid observations, preserves user exclusions, and sorts by time. Quantitative use still requires suitable acquisition and a valid internal standard.

`fitKinetics(points, model)` fits included observations with linear regression or offset exponential growth/decay. Exponential parameters include `timeOrigin`; evaluate the exponent with `time - timeOrigin`. Predictions and residuals follow the input point order. The legacy `exportKineticsCSV(points, fit?, context?)` can additionally report target/standard areas, invalid rows, units, region settings, and the stack label. Predictions join measurements by spectrum ID.

Portable `.webnmr` archives retain optional stack definitions, active stack identity, validated project/spectrum appearance settings, and processing recipes. Earlier version-1 archives remain readable. Members must reference existing spectrum IDs, and a stack reference must belong to that stack. Original, processed, and FID arrays use binary Float64 values. Local recovery uses IndexedDB structured cloning. Kinetic targets, regions, per-target proton counts/models, standard settings, exclusions, series membership, time-fill presets, view and fit-enabled state are retained in portable projects and recovery. Acquisition times belong to spectrum records.

`buildKineticsWorkbook` exports browser-native OOXML using fflate, without a server upload. The workbook contains a report plus one numerical sheet per target, with editable ln(signal)/reciprocal formulas, cached values, slope/R² formulas and native scatter charts. Browser rendering supplies the embedded PNG figures; a separate ZIP exports those figures. Order regressions exclude nonpositive observations and use the same user exclusions. Raw signal plots include signed valid observations. Offset exponential fits are kept separate from zero-offset order linearizations.

## Excel spectrum reports

`spectrumReport.ts` builds a standalone OOXML workbook using the existing `fflate` dependency. `buildSpectrumWorkbook(spectrum, options, figure?)` exports the current processed numerical arrays, without replaying recipes, applying display gain or replacing source data. The first 1D `Spectrum` sheet contains referenced ppm and full-precision corrected real values, optional imaginary values, and the current-view graphic at E2. Excel's 1,048,576-row limit is handled by additional numeric sheets; the last million-point carbon sample is retained.

The following `Analysis` sheet recomputes signed trapezoidal integral areas from the exported trace and referenced region limits, then calculates normalized values using the current calibration. The normalization factor is stored once and normalized cells use editable formulas with cached values. Picked peaks and multiplets are optional; chemical shifts, intensities and individual J values remain numeric. Display gain does not enter any measurement. Existing analysis identifiers and labels remain literal strings, including labels that begin with an Excel formula character.

`Spectrum figure` stores the exact SVG supplied by the current plot, with a PNG fallback in the same drawing for older Excel versions. The first 1D sheet reuses these media with its own drawing relationship. A standalone SVG download is enabled by default. SVG display depends on viewer support; the fallback remains independently loadable. Optional `Processing` records current phase, baseline, windows, reference offsets, source metadata, comments and history. The figure shows the current view while numeric sheets contain the entire processed dataset.

For 2D, the first sheet contains the complete row-major real matrix with independently referenced F1 rows and F2 column headers. Optional F2, F1 and double-imaginary planes get their own sheets. Wide matrices partition at Excel's column limit without flattening or dropping samples. A 2D figure remains on its figure sheet; 1D integral/peak/multiplet tables are explicitly not presented as 2D measurements.

`spectrumReportClient.ts` builds the workbook in a separate worker. Acquisition arrays and duplicate immutable source matrices are omitted from the worker snapshot. Preflight runs before snapshots/copies. Export is bounded to 4.5 million numeric cells and a 192 MiB uncompressed package; oversized exports report the limit and suggest omitting imaginary values or using CSV. No silent downsampling occurs. PNG rendering is limited to eight million pixels. The compact dark `SpectrumExportDialog` captures the data snapshot before asynchronous export, supports cancellation and keeps trusted-click Excel/SVG download links available after attempted automatic downloads. Callback changes do not abort the job or revoke those links.

Regressions cover current corrected values versus originals, display-gain exclusion, recalculated signed integrals/calibration, full numeric precision, optional tables, literal labels, SVG/PNG relationships and first-sheet anchors, actual 2D axes/quadrants, row partition boundaries and memory limits. A saved sample workbook was independently imported/recalculated and its tables rendered; an independent reader loaded both PNG fallback placements.
