Learned proton couplings in the browser
=====================================

The FullSSPrUCe default ETKDG coupling checkpoint is exported from the original
PyTorch model at revision `de4fcad693eccca469b12e3505d8c3d8fe2458d5`.
The browser uses this float32 ONNX graph, not a rule table or guessed J value.

The Decode14 model includes eight edge and vertex GRU iterations, layer norms,
256 latent features, fourteen coupling type embeddings, and ten bootstrap heads.
Its original 64-atom padding is retained, including contributions of padded GRU
states to edge-to-vertex means. Inputs contain 94 atom and 119 spatial/bond
features. Unsupported molecules with more than 64 explicit atoms are rejected.

Predicted mean J values keep their sign. The standard deviation is exactly the
upstream unbiased variance over ten heads plus 1e-5, square-rooted, in Hz. It
measures model disagreement and is not a calibrated experimental error bar.
The emitted proton pairs cover the trained 2-, 3-, and 4-bond H–H categories.
Longer-range proton pairs are excluded, not substituted with typical couplings.
The upstream model also trained one-bond C–H couplings; this proton-only API
does not emit those. Pair indices refer to the explicit-H molecule and do not
collapse protons attached to the same atom.

`predictLearnedCouplings(features, options)` lazily loads ONNX Runtime WASM from
local static assets and checks model SHA-256 against the pinned export. No
molecule, feature, geometry, or prediction is sent to a remote inference service.
`disposeLearnedCouplingModels()` releases cached sessions. Tensor inputs/outputs
are disposed after each evaluation, including canceled requests.

Rebuild with `scripts/couplings/convert_model.py /path/to/fullsspruce-public`.
The original checkpoint SHA-256 is pinned before deserialization. The model
source declares MIT in upstream `setup.py`; attribution and that declaration
are retained in `public/prediction/couplings/NOTICE.txt`.

Numerical validation (2026-10-04): five supplied-conformer molecules cover
ethanol, butane, aspirin, a chiral alcohol, and zwitterionic glycine. The browser
builds its own features from the aligned explicit-H ensembles and matches the
pinned native RDKit 2025.09.1 feature arrays exactly. Comparing all 40,960 mean
and standard-deviation values against the unchanged PyTorch model gives maximum
browser WASM errors of 0.0000610352 Hz (mean) and 0.00000801683 Hz (standard
deviation). All 49 negative emitted H–H values retain their signs. The packaged
worker uses only same-origin assets. On this machine, first inference including
session setup took 1.119 s and a cached repeat took 0.760 s; the HTTP cache may
already have been warm. These checks establish port parity, not new experimental
accuracy or calibrated uncertainty.

The independent native ONNX comparison is reproducible with
`scripts/couplings/validate_onnx.py`; native PyTorch fixtures are generated by
`scripts/couplings/generate_reference.py`. Open
`/scripts/couplings/browser-validation.html` on the local Vite development site
to run the feature-to-model worker check. This page is a development harness,
not included in the normal application build.
